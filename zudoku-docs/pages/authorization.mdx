# Authorization

The Ticketing System API uses **API-key authorization**, passed in a request
header. The security scheme is described in the OpenAPI document
(`components.securitySchemes.APIKeyHeader`):

```yaml
components:
  securitySchemes:
    APIKeyHeader:
      type: apiKey
      in: header
      name: X-API-Key
```

## How to pass the key

Every request to the API (except `/openapi.json` and `/docs`) must include the
header:

```
X-API-Key: demo-key-123
```

Example request with `curl`:

```bash
curl -H "X-API-Key: demo-key-123" http://localhost:8000/events
```

In the generated SDK (see [Installation](/installation)), the key is passed via
`AuthenticatedClient(..., token="demo-key-123", auth_header_name="X-API-Key")`.

## Error codes

| Code | When it occurs |
| --- | --- |
| `401 Unauthorized` | The `X-API-Key` header is missing or contains an invalid key |
| `404 Not Found` | The entity (event, ticket, user, etc.) with the given id was not found |
| `409 Conflict` | An invalid operation: the event is sold out, or an impossible ticket status transition was requested |

> In this learning project `demo-key-123` is the only valid key, hard-coded in
> `api/main.py`. In a real system, keys would be stored in a database and
> issued individually to each client.
